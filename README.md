## 项目介绍

ClassTopLand Next 将当天课程、上下课倒计时和日期显示在桌面课程条上，适合在教室电脑上查看课程安排。通过系统托盘快捷面板，可以打开设置、编辑档案和切换课表。

项目使用 C++17、Qt Widgets 和 ElaWidgetTools-Plus 构建界面，使用 JSON 保存配置与档案，并支持 ClassTopLand tables.json 和 CSES 格式课表交换。下文描述的是当前源码实现；构建步骤以 Windows x64 为例。源码包含 Linux / macOS 的部分平台处理，但当前构建配置仍需适配，本文不承诺这些平台已完成构建与运行验证。

### 课表匹配说明

- **自动匹配**：按当天星期与周模式选择课表；多张课表同时匹配时，需要在托盘快捷面板中手动选择。
- **手动选择**：在快捷面板的「切换课程表」中指定周课表，选择会保存到当前档案。恢复「自动匹配」后重新按日期匹配。
- **学期与单双周**：在档案编辑的“基本信息 → 学期设置”中设置学期第一天，该日期所在周为第 1 周（单周），每周一切换周次。托盘选择“自动”后可按单周 / 双周匹配课表；未设置学期日期时仍可手动选择课表。
- **日期安排**：调休、换课与代课保存在当前档案中，仅对指定日期生效，重启后保留。来源日的科目、时间或课程数量变化，以及来源被删除时，关联安排会自动取消并提示；仅改名称或课程列表顺序不取消。可在调休窗口或换课 / 代课窗口恢复该日期全部特殊安排。
- **跨天换课**：换课 / 代课窗口左右两侧可独立选择今天或未来日期，默认显示当天课表；有多个匹配时可手动指定周课表。已有调休、换课或代课时，在当前结果上继续交换，两端结果一次性保存。特殊安排按日期独立处理：恢复某天、该天来源失效或过期清理时，只影响该日期，另一端的换课结果继续保留。
- **代课**：在“换课 / 代课”窗口切换到“代课”，左侧选择日期和课程，右侧以网格显示当前已保存档案的全部科目，点击选中后确认即可保存；网格随窗口宽度调整列数，科目较多时可滚动查看。已有调休、换课或代课时，在当前结果上继续替换；恢复日期会清除该日期全部特殊安排。仅被特殊安排引用的科目改名时同步课程引用，删除前需先修改对应课程或恢复日期；来源日发生变化时仍按日期安排规则取消。
- **自动清理**：启动时、每分钟及档案提交时清理过去日期记录，保留今天与未来安排；课程条关闭时也会清理。非当前档案在加载时清理。

## 开始使用

可在 [Releases](https://github.com/Aero8m/ClassTopLand-Next/releases) 页面查看发布包；使用源码时，请参照下方构建步骤。

运行程序前，Windows 需已安装 Visual C++ v14 x64 运行库。若尚未安装，请先从微软获取并安装。[Visual C++ 运行库官方页面](https://learn.microsoft.com/zh-cn/cpp/windows/latest-supported-vc-redist?view=msvc-170)

1. 启动程序。首次运行会在用户主目录下创建默认配置和 `Default` 档案。
2. 单击或右击系统托盘中的程序图标，打开快捷面板，进入「档案编辑」。
3. 在「基本信息」中填写档案名称，在「科目管理」中添加科目，再到「课表管理」创建周课表、设置适用星期并添加课程。也可以先在「时间线管理」中整理时段，再应用到当天课表。
4. 点击「保存」或按 `Ctrl+S` 保存档案，课程条随即刷新。编辑窗口中的未保存更改需要保存后才会生效。
5. 在「设置 → 课程条」中调整组件和高度，在「设置 → 外观」中调整主题。课程条左侧按钮用于展开与收起。

也可以在「设置 → 档案管理 → 导入档案」中导入 [示例档案](./examples/profiles/Test.json)，再选中它并点击「切换并重启」。示例包含多种科目与课程时段，可用于体验课程显示。

关闭设置或编辑窗口后，程序仍在托盘中运行。需要结束程序时，请使用快捷面板底部的退出按钮；切换档案会重启程序，并先处理编辑窗口中的未保存更改。

同一用户数据目录仅允许运行一个实例。重复启动会显示“程序已经运行”弹窗并退出，可从系统托盘打开已有程序；正常重启、切换档案与 UIAccess 权限切换按原有流程交接。异常退出后再次启动会自动回收失效的实例锁。

### 软件更新

从 Autobuild 安装支持更新的 Windows x64 版本后，可以在「设置 → 更新」查看新的自动构建和更新日志。点击「下载并安装」后，应用通过 Autobuild 下载完整安装包并校验大小和 SHA-256。退出前会处理未保存的档案及插件草稿，然后请求管理员授权。安装只显示进度，成功后自动启动新版。拒绝授权会恢复启动原程序。安装器要求重启 Windows 时，应用会提示手动重启。

「自动更新」默认关闭。开启后，应用在启动约 15 秒后首次检查，之后每 6 小时检查一次。发现新版本后在后台下载并校验。安装包就绪时，托盘退出按钮提示「退出并安装更新」。退出时先处理未保存内容，再按 Windows 要求请求授权。完成后台准备的更新后，应用保持退出状态。在更新页选择「立即安装」可安装后自动启动新版。

使用旧版本时，请先从 [Autobuild](https://autobuild.aero8m.cn/ClassTopLand-Next) 手动安装一次支持更新的版本。源码构建和便携运行也可通过该目录手动下载安装包。

### 提醒

在「设置 → 提醒」中设置总开关、上课／下课／课前提醒的独立开关、课前提前分钟数，以及三类提醒的文本。默认保持上课、下课和课前 2 分钟提醒；文本支持 `{科目}`、`{节次}`，也可填写固定文字。结束编辑后保存，可恢复默认文本或测试展示。空白文本不能保存；保存失败时原设置继续生效，输入内容保留以便修改或重试。

自定义规则随当前档案保存，可新增、编辑、删除和启停。星期按**课表来源星期**判断：例如周六调休使用周一课表，匹配周一规则。课程可选不限、指定科目或当天第 N 节，节次按实际开始时间排序，课程内容使用调休、换课、代课和单双周匹配后的结果。科目改名会同步规则引用；删除科目后保留规则并显示“科目不存在”，暂停触发，重新指定科目后可恢复。

规则时间支持固定时刻，或相对上课／下课的准点、提前及延后。固定时刻每天最多提醒一次，指定课程条件时要求当天存在匹配课程，提醒文本使用固定文字；相对时间对每节匹配课程分别触发，支持课程占位符，计算结果跨日时跳过。普通提醒与自定义提醒独立生效，同一时刻触发时依次展示。

提醒仅在应用运行且课程条启用时展示，关闭设置窗口后继续运行，不依赖是否添加课程查看或倒计时组件。收起的课程条会自动展开，文字默认停留 5 秒；长文本省略显示，悬停可查看全文。启动、修改规则、课表重载和休眠恢复不补发过期提醒。测试展示使用示例课程，不消耗正式触发记录；本功能不播放声音，也不显示独立弹窗。

通用设置保存在 `MainConfig.json` 的 `config.reminderConfig`，自定义规则保存在档案的 `profile.reminderRules`。旧文件缺少字段时使用默认值；原生 JSON 备份与档案复制保留规则，CSES 和旧版 tables.json 不携带提醒规则。全局提醒设置不随档案导出。

### 桌面倒计时（DesktopCountdown）

在「设置 → 桌面倒计时」中开启功能，填写中英文事件名称和目标日期时间。倒计时使用原版 DayTimer 的透明背景、字体和红白灰配色，独立显示在桌面底层，不随应用主题色变化；到期显示「一天不剩」。它与课程条中显示上下课剩余时间的「倒计时」组件相互独立。

默认使用毫秒显示，每 50ms 刷新；可选择秒级显示，每秒刷新。默认布局沿用原版 ClassTopLand 的 721×330 透明画布及外围留白：画布靠所选屏幕右侧，纵向位置为「屏幕高度减去画布高度」的 95%，并随 50%～200% 的整体缩放调整。数字与单位按当前数字的实际宽度排布；普通数字变化时保留画布位置，过长数字需要时扩展画布以免裁切。可见内容超出屏幕可用区域时会限制位置。

在「布局方式」中选择「自定义可见边距」，可按可见内容边缘设置右侧、底部边距，默认各 24 个逻辑像素；边距不包含透明留白，也不随整体缩放放大，内容宽度变化时位置随之调整。切换回原版布局时保留这些边距数值，但不应用。两种布局均支持选择显示屏；目标屏幕断开时临时回退主屏，重新连接后恢复。内容过大时缩小至可用区域内，不修改已保存的设置。长事件名称以省略号显示，悬停可查看完整文字。

设置修改后立即保存生效，文本在结束编辑时保存；保存失败时保留原设置。配置位于 `MainConfig.json` 的 `config.desktopCountdownConfig`，包含 `enable`、`targetDateTime`（本地时间 `yyyy-MM-ddTHH:mm:ss`）、`labelTag`、`englishTag`、`showMilliseconds`、`screenName`、`useLegacyPlacement`、`rightMargin`、`bottomMargin`、`scalePercent`。`useLegacyPlacement` 默认为 `true`，旧配置缺少此字段时也使用原版布局，设为 `false` 时启用自定义可见边距。空屏幕名称表示跟随主屏。现有配置缺少该节点时默认关闭功能，主配置格式版本为 2，旧版 v1 配置在加载时原子迁移；不自动读取旧项目的数据。

### 集控（云端同步）

新版设备可在管理网页上直接调整当前生效档案的指定日期，也支持通知、应用重启、切换云端档案及 Build 查看。后台执行结果记录在设备详情。收到常规课表 v2 时保留来源仍匹配的临时安排。

设备截屏默认随 Windows 目标编译，可用 `-DCTX_ENABLE_SCREEN_PREVIEW=OFF` 关闭。管理员在设备详情请求截屏后，客户端从本地交互会话的指定显示器抓取一张 JPEG，最高 1920×1080，并保留 Windows 采集标识。远程关机和重启复用客户端的设备配对，要求客户端在线，且运行客户端的 Windows 账户拥有「关闭系统」权限。

「设置 → 集控」用于接入 CTX-Server 集控服务。默认服务器地址为 `https://ctx.aero8m.cn`，可在该页修改；非本机地址必须使用 `https://`，本机联调可使用 `http://127.0.0.1`。在管理网页生成 12 位配对码（有效期 10 分钟）后填入并配对；配对成功会创建专用「云端档案」（复制当前档案内容），并自动切换为当前档案（需重启一次，编辑窗口的未保存更改会先按现有流程处理）。

同步默认开启，按服务端建议的 20～30 秒间隔轮询，网络失败使用指数退避，恢复后回到正常间隔。课表档案与展示配置为两个独立通道，分别下载、校验 SHA-256、原子应用并发送回执；某个通道失败不会阻塞另一个通道。内容保存成功后才会更新已应用代次，下载成功本身不算应用成功。

- **课表档案**：新版本更新「云端档案」的周课表、手动选择和提醒规则。常规课表 v2 还会保留来源仍匹配的临时安排，原生档案 v1 则会应用载荷里的日期安排。应用后仍可在本地切换课表、调休、换课及代课。当前档案有未保存编辑时上报 `local_edit`，保存或放弃后自动重试。
- **展示配置**：每次新发布覆盖课程条组件列表、课程条高度与间距、外观和桌面倒计时的受管设置。课程条布局整表替换，包括移除本机添加的插件组件。档案路径、UIAccess、插件授权、屏幕选择和全局提醒由设备管理。配置格式 v2 可明确下发窗口规则（完整替换）与插件启用偏好（按 ID 合并）。省略时保留本地值。窗口规则保存后重新加载，失败返回 `window_rules_apply_failed` 并可重试。插件偏好下次启动生效，未安装或未授权的插件不会自动运行。客户端同时支持配置格式 v1/v2。云端倒计时目标是无时区的本地时间。

设备凭证与同步状态保存在 `ClassTopLand-Next_Data/cloud/state.json`，崩溃恢复用的待应用内容位于 `cloud/pending/`，云端受管档案位于 `profiles/`。凭证不会写入 `MainConfig.json`，也不会随档案导出；备份或分享数据目录时请注意该文件包含设备凭证。应用顺序为「内容原子落盘 → 已应用标记与待发回执原子落盘 → 发送回执」，异常退出后重启会补完未结束的应用或回执。

设备凭证被管理员撤销后，同步会停止并在集控页提示重新配对；手动修改或损坏状态文件不会导致凭证被静默重置。解除绑定会删除本机凭证和同步状态、保留云端档案内容，服务器上的设备记录仍需管理员撤销。管理员可在原设备详情页签发重新配对码，客户端在「设置 → 集控」输入即可接回原设备记录。成功后换用新凭证，返回同一设备 ID 时保留本机的同步状态。

### JavaScript 插件

在“插件中心 → 插件管理”管理本地插件。通过“更多 → 打开插件目录”放入插件包，再重新扫描、检查权限并启用。仓库提供 [示例插件](examples/plugins/) 和 [开发文档](docs/plugins/README.md)；新插件默认停用，扫描不会执行插件代码。

插件使用清单 v3、JS API v2 的 `.ui` 原生页面与 JS 控制器；有页面时通过 `contributions.mainPage` 指定唯一默认页面，每个插件只有一个侧栏入口，内部使用 ElaPivot 切换功能、设置和组件实例设置页签；页面由宿主管理背景和滚动，新设置页使用共用原生分组、设置行及操作栏，功能页在统一容器中编排 Qt/Ela 业务控件，插件自行实现校验与保存。旧页面兼容加载并提示。课程条仅允许标准横向 `CourseBarItem`，文字、高亮及进度外观与内置组件共用实现，可通过 `leftMargin` / `rightMargin` 覆盖展示项左右边距。切换页面保留草稿，关闭中心、停用、重载和退出时提供保存、放弃和取消。插件课程条组件从“设置 → 课程条”添加，实例设置在插件中心打开并独立保存。关闭插件中心不停止后台任务。旧清单或 API v1 插件显示“需要升级”，原有数据与课程条配置保留。

仅安装可信插件：独立工作线程不提供进程级安全沙箱，UIAccess 模式下插件共享宿主进程权限。可使用 `--disable-plugins` 启动参数或插件管理菜单进入恢复模式；故障插件不自动重复启动。替换源文件后重新扫描，在插件详情中确认权限并「热重载」。激活或配置保存失败会恢复上一运行版本。卸载默认保留私有数据。

### AI Agent

在系统托盘快捷面板打开「AI Agent」。左侧按工作区组织会话，一体式圆角输入区左下角的目录菜单切换工作区；编辑目标插件由 AI 根据任务选择，旁边选择本会话的工具权限，右下角选择模型和思考强度。Enter 发送，Ctrl+Enter 换行。点击圆形发送按钮进入对话，运行时此按钮切换为「停止」，可中断请求并结束正在运行的命令进程组。中断或失败后，可点击「继续执行」发送「继续」。恢复任务时会先核对实际文件和已执行结果，不自动重放上次命令。发送按钮与用户气泡的强调色跟随「设置 → 外观 → 主题色」。

对话区采用右侧用户气泡和无边框 Agent 正文。思考与工具操作按时间顺序排列，每条中间消息之后开始新的可展开分组；仅最终答复显示复制按钮，每轮结束另显示耗时。对话区和展开的思考区会自动跟随最新内容，向上滚动时暂停，回到底部后恢复。对话区也可点视口底部的透明悬浮箭头回到最新消息。长消息默认渲染前 24 Ki 字符，可查看完整内容；展开的思考过程以 Markdown 富文本渲染，高度随内容增长，最高为 200 个逻辑像素，超出该高度时可在思考区内滚动查看，过长时显示截断提示。任务不设固定模型步骤数或工具调用总次数上限，直到模型完成、用户停止或发生错误；单次命令超时和流式数据大小限制仍然保留。

流式处理分别限制实际正文、思考及工具参数（合计 16 MiB）、单个 SSE 事件（4 MiB）和总传输量（128 MiB），避免将逐 token 重复的协议包装误当作实际输出。超限或断流时不会执行未完整接收的工具调用。

DeepSeek 默认开启高强度思考，可从模型菜单的「思考强度」切换为关闭、低、高或最高，选择随会话保存，并在每轮开始时固定。模型返回思考内容时，对话显示可展开的思考卡。过程仅在本次运行期间暂存最近步骤，本地历史只保存思考状态；连续工具调用期间会按协议回传原始 `reasoning_content`。其他供应商保持模型自身默认行为，不附加 DeepSeek 专用参数。参数说明见 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

在「设置 → AI Agent → 模型供应商」添加供应商。内置 DeepSeek、Kimi、GLM、OpenCode Go、千问百炼和 OpenAI 地址，也可填写支持 Chat Completions 的 Base URL。一个供应商可配置多个模型，支持手填、获取候选模型和测试。API Key 保存在 Windows 凭据管理器，已有连接和会话可继续使用。

在「工作区与历史」添加目录并设置默认工作区；首次使用或已有配置没有该字段时，默认工作区为用户目录，旧会话中未选择工作区的记录也会回填为默认工作区，之后可随时改回「无工作区」。会话历史默认保存在本机，可关闭或清除。获准执行的工具会将结果直接发送给当前模型。文件工具支持绝对路径和相对于当前编辑目录的路径；选择插件后保留原工作区的读取能力，没有工作区时仍可通过绝对路径使用文件工具。读取、列目录和搜索优先使用内置文件工具，超出本轮可读范围时由宿主自动展示额外目录授权，不需要模型另行申请或改用系统命令。系统命令（Windows 使用 PowerShell）使用当前普通用户权限，当前编辑目录作为命令的起始目录。

- **只读**可对话、读取工作区或已安装插件文件，以及查看版本历史；可确认本轮额外目录读取，不能修改文件或执行系统命令。
- **审批**额外目录读取、每次普通文件修改、启动应用和执行命令需要确认；修改的目标目录授权与具体变更在同一张确认卡中展示。打开插件默认只查看，实际编辑时确认本轮对该插件的编辑授权；也可通过 `open_plugin access=edit` 提前申请。系统命令仍单独确认，新会话默认使用此档。
- **YOLO**在输入区显示为「完全访问」，可直接读写普通目录、启动应用和运行命令，不受当前工作区范围限制；插件编辑授权、首次启用和新增插件权限仍必须确认。重启后恢复「审批」。

额外目录授权仅对本轮任务有效，结束、失败、停止或恢复任务后重新确认；不会从会话历史或恢复摘要恢复权限。读取文件时确认其父目录，列目录和搜索时确认目标目录，确认卡显示完整路径、访问类型和有效期。用户拒绝后，本轮不自动重复申请，也不得通过系统命令绕过拒绝。

模型可用的插件工具还包括按主题读取 SDK、业务动作发现与调用、不弹出窗口的后台隔离预览、控件树／属性／交互检查、日志和供用户查看的截图；文本模型不会接收截图。预览使用临时数据并禁止外部网络。模型可用的工具包括文件列表、按行读取、文件与内容搜索、创建、编辑、删除、重命名和多文件批量修改，以及 `shell`、`open_application`、结构化任务计划和插件工具。文件工具在宿主确认目录访问后执行，始终拒绝符号链接、重解析点、设备路径、`..` 和备用数据流；授权不能解除格式、大小或运行模式限制。修改已有文件前需要先读取，文件被外部修改时返回冲突。重命名检查源和目标目录，多文件修改在全部授权、指纹和插件检查点预检完成后执行，失败时恢复本批已写文件。普通目录授权不能替代插件编辑授权，运行副本和回滚记录不可直接修改。PowerShell 使用普通用户权限，工作目录只是命令的起始目录，并不限制命令可以访问的位置。

命令卡片跟随应用主题，展开后上方显示工作目录、完整原始命令及复制按钮，下方用等宽字体实时显示输出，保留缩进并支持横向滚动；输出区随内容增长，最高 320 个逻辑像素。运行状态、耗时和最终退出码与原始命令分别保存，流式更新不会覆盖输入；向上阅读或选中文本时不强制滚动。stdout 与 stderr 分别采集，后者在输出中以 `[stderr]` 标识，PowerShell CLIXML 转换为可读文本，解析失败保留原文。实时与历史使用相同卡片，旧记录缺少命令时显示「原始命令未记录」；失败原因、超时、中断和截断状态明确展示。命令超时默认 60 秒，可指定 1～600 秒；输出最多保留 256 KiB，超限明确标记。文本文件最大 2 MiB，读取和搜索支持分页。任务计划按待处理、进行中、完成显示并保存；模型上下文窗口未知（配置为 0）时默认采用 128K（131,072 tokens），已配置的正数值优先；上下文按 token 估算接近模型窗口预算时压缩较早操作，保留当前用户请求、完整 SDK，以及最近一组助手调用和全部工具结果（含思考协议字段）；本轮已确认的插件编辑授权由宿主另行提供，不因压缩而重新申请。若完整 SDK 或最近工具结果仍无法放入预算，会明确暂停并保留恢复记录，可调整模型上下文或分页读取后继续，不会丢弃结果后反复调用相同工具。任务恢复记录不保存原始思考或待执行工具调用；关闭历史保存后不再写入新的恢复记录，清除历史会一并清除恢复记录。

插件开发直接使用源文件：对 Agent 说明要修改的插件后，Agent 通过 `list_plugins` 和 `open_plugin` 自行选择插件，默认只查看；实际修改时由宿主向用户申请本轮编辑授权，无需手动选择插件或配置工作区。完全访问（YOLO）也不能跳过该授权；只读查看不授予编辑权限。授权仅对本轮和指定插件有效，新一轮修改或继续应用未完成修改需要重新确认。手工安装与 Agent 创建的插件均支持多文件包，保留实际入口、资源、插件 ID、贡献 ID 和实例配置。Agent 创建的插件就是普通 JS 插件，统一从 `plugins/` 扫描，使用相同清单、权限、运行副本和管理入口。

每轮首次修改前自动备份整个插件包；本轮结束时自动校验和热重载。编辑过程中继续运行旧版，校验、激活或保存失败时保留源文件并恢复旧运行版本。已停用插件更新后保持停用；新插件首次启用以及权限扩大时在对话内确认。插件表单有未保存内容时仍通过保存／放弃／取消处理。增强置顶或管理员模式下保留对话、历史和审阅，Agent 系统操作及插件修改不可用；已创建或修改的插件按普通插件规则运行，不因来源额外限制。恢复模式跳过全部插件自动启动，仍可在插件设置中手动启用或热重载。

对话中的插件结果卡片提供「查看差异」「撤销本轮修改」和「版本历史」；也可以在「插件中心 → 插件管理 → 详情 → 版本历史与回滚」恢复历史版本。每个版本保存该轮修改前的代码与资源，默认保留最近 20 组，当前运行版本和待恢复版本受保护。回滚前先备份当前文件，回滚失败恢复原状态。回滚不恢复插件私有数据、插件设置或课程档案；插件自行写入的数据与外部副作用不属于代码回滚范围。

源包位于数据目录的 `plugins/`，运行副本位于 `plugin-versions/`，修改历史位于 `plugin-history/`，回滚恢复日志位于 `plugin-recovery/`。异常中断后不自动执行未验证源文件。旧草稿保留原文件；有旧草稿时，设置中显示「旧草稿恢复」，可审阅差异并在创建检查点后恢复到源目录，不再要求经过草稿开发流程。

主配置现为 v2，兼容读取并原子迁移 v1，迁移失败保留原文件。旧程序不能读取 v2，回退应用版本前请备份数据。

### UIAccess 增强置顶（Windows）

在「设置 → 课程条 → 基本设置」中开启「UIAccess 增强置顶」，程序会请求当前用户的管理员授权，并在新实例初始化成功后自动重启。关闭开关也会自动重启，撤销 UIAccess 并恢复普通置顶。未保存的档案编辑会先提示处理；取消退出、取消授权或权限获取失败时保留原实例和原设置。

开关默认关闭，并保存在 `MainConfig.json` 的 `courseBarConfig.uiAccessEnabled` 中。开启后，从桌面快捷方式重新启动通常仍需 UAC 授权；已取得 UIAccess 时，托盘重启和切换档案会复用权限。冷启动获取权限失败时回退为普通置顶并保存关闭状态；如果配置只读，则仅本次运行采用回退状态，并说明磁盘配置未改变。

实现参考 [killtimer0/uiaccess](https://github.com/killtimer0/uiaccess) 的令牌获取思路，无需代码签名或固定安装目录。该模式的最终实例保留当前用户的管理员权限，要求同一用户授权，不支持改用另一个管理员账户。关闭时通过 Windows 桌面 Shell 启动普通实例；系统策略或桌面 Shell 不可用时会提示切换失败。此功能不保证覆盖独占全屏程序或 UAC 安全桌面。非 Windows 平台禁用该开关。

### 窗口拦截（Windows）

在「设置 → 窗口拦截」中刷新当前窗口列表，选中窗口后可「仅隐藏一次」，或填写可选的「标题包含」条件并点击「隐藏并保存」。规则同时匹配程序完整路径和窗口类名；路径及标题匹配忽略大小写，窗口类名区分大小写。标题条件留空会匹配该程序中所有同类窗口。

保存的规则从应用启动时生效，无需先打开设置；关闭设置后仍会监听新显示的窗口。「恢复并停用」或「删除规则」会恢复本次隐藏且未被其他启用规则拦截的窗口。若窗口还受其他规则匹配，请先停用相应规则。来源未知的隐藏窗口仅在手动点击「恢复所选窗口」时恢复。正常退出或重启会恢复本次隐藏的窗口；程序异常终止时不保证恢复。

规则保存在 `MainConfig.json` 的 `config.windowInterceptionConfig.rules` 中，包含 `exePath`、`className`、`titleContains` 和 `enabled`，与当前课表档案无关。旧版配置缺少此节时使用空规则列表，不自动读取 ClassTopLand 的 `window_rules.json`。非 Windows 平台显示不可用说明并保留规则配置。窗口权限不足或监听失败时会提示原因。

## 从源码构建

### 环境要求

| 依赖 | 要求 / 用途 |
| --- | --- |
| C++ 编译器 | 支持 C++17；以下 Windows 示例使用 MSVC 2022 x64 工具链 |
| Qt | 6.9 或更新版本，包含 Core、Gui、Widgets、Qml、Network 及匹配版本的 Widgets 私有开发文件；当前工程路径使用 Qt 6.9.3 `msvc2022_64` |
| CMake | 4.0 或更新版本，与根目录的最低版本声明一致 |
| Ninja | 用于下方的单配置构建命令 |
| Git | 克隆仓库及初始化依赖子模块 |
| ElaWidgetTools-Plus | Git 子模块，随项目源码构建，默认生成动态库 |
| yaml-cpp | Git 子模块，随项目源码静态构建，版本由子模块提交固定 |

克隆仓库及初始化子模块时，需要能访问 GitHub 以获取依赖；子模块就绪后，CMake 配置无需下载 yaml-cpp。Qt 套件必须与编译器及目标架构匹配；使用 MSVC 套件时，还需安装对应的 Visual Studio C++ 构建工具和 Windows SDK。

### 1. 获取源码与子模块

```powershell
git clone --recurse-submodules https://github.com/Aero8m/ClassTopLand-Next.git
cd ClassTopLand-Next
```

已经克隆仓库时，在项目根目录补充初始化：

```powershell
git submodule update --init --recursive
```

### 2. 设置 Qt 路径

未指定 `CMAKE_PREFIX_PATH` 时，[CMakeLists.txt](./CMakeLists.txt) 默认使用 `C:/Qt/6.9.3/msvc2022_64/lib/cmake`。安装位置不同时，在配置命令中传入实际 Qt 套件根目录或 `lib/cmake` 目录，无需修改源码：

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="D:/Qt/6.9.3/msvc2022_64"
```

Qt DLL 部署路径根据实际找到的 `Qt6_DIR` 计算，也支持传入多个包搜索前缀。

### 3. 配置并编译

在 **Visual Studio 2022 Developer PowerShell** 中启用 x64 构建环境，确保 `cmake`、`ninja` 与 `cl` 可用，然后在项目根目录执行：

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

可执行文件位于 `build/ClassTopLand-Next.exe`。调试构建可以另用 `build-debug` 目录，并将 `CMAKE_BUILD_TYPE` 改为 `Debug`。

这里使用单配置的 Ninja 生成器，因为当前 Windows DLL 复制逻辑依据 `CMAKE_BUILD_TYPE` 判断 Debug / Release。更换编译器、生成器或 Qt 套件时，请使用新的构建目录。

Windows 构建应在正常桌面权限的 IDE 或开发者终端中进行。沙箱生成的构建目录可能继承 Low（低完整性）标签，使 EXE 从 CLion 或资源管理器启动后仍处于低权限，导致配置写入被拒绝、托盘异常和 UIAccess 交接失败。构建后会自动把本项目 EXE 的完整性标签设为 Medium，并保留其原有访问权限；无法完成时构建报错，避免把受限产物当作可运行版本。无需始终以管理员身份运行程序；只有启用增强置顶时才请求提权。

### 4. 部署与运行

Windows 构建会复制 ElaWidgetTools 动态库，并自动调用同套件的 `windeployqt` 部署 Qt Qml、Network 和 TLS 后端。分发前仍应在无开发环境的机器验证；需要重新部署时可执行：

```powershell
& "C:/Qt/6.9.3/msvc2022_64/bin/windeployqt.exe" --release .\build\ClassTopLand-Next.exe
.\build\ClassTopLand-Next.exe
```

分发时请保留部署后的 DLL 和插件目录。制作支持应用内更新的安装包时，还需随主程序打包 ClassTopLand-Next-Update.exe。Debug 构建请改用对应构建目录和 `windeployqt --debug`。

### GitHub Actions 自动构建

仓库提供 [Windows Autobuild](./.github/workflows/windows-autobuild.yml) 工作流：

- 推送到 `main`：编译 Windows x64 Release、制作安装包、上传 Actions artifact，并在原仓库 `Aero8m/ClassTopLand-Next` 发布自动构建正式版本并设为 Latest。
- 向 `main` 提交 PR：编译、打包并上传 artifact，不发布 Release。
- 手动构建：在 Actions → Windows Autobuild → Run workflow 选择分支；默认只生成 artifact。在 `main` 上勾选 `publish_release` 可同时发布正式版本并设为 Latest。

流程使用 `windows-2022`、MSVC 2022 x64、Qt 6.9.3、CMake 4.0.3 和 Ninja。runner 自带的 CMake 可能低于项目最低要求，因此工作流会单独安装固定版本。Qt 安装结果通过 Actions cache 复用；源码及两个子模块每次按对应提交检出。

安装包文件名中的构建标识取实际检出提交的前 7 位，工作流仅在临时工作区替换 `src/VERSION.h` 中的 `|BUILD_VERSION|`。CMake 保留 EXE 完整性标签规范化与 Qt 部署步骤；随后独立整理打包目录并用 `windeployqt` 部署运行依赖，最后调用 [Inno Setup 脚本](./packaging/windows/setup.iss) 生成：

```text
ClassTopLand-Next-setup_build_<7位提交号>-amd64.exe
```

简体中文安装语言文件随仓库保存在 [packaging/windows/languages/ChineseSimplified.isl](./packaging/windows/languages/ChineseSimplified.isl)，安装脚本直接按相对路径引用，不依赖本机或 runner 额外安装中文文件。文件取自 [Inno Setup 上游固定提交](https://github.com/jrsoftware/issrc/blob/6ef32198ef1f7b7b375cd4b6b90896c2a58eb4c2/Files/Languages/ChineseSimplified.isl)，保留原作者说明及 [许可证](./packaging/windows/languages/LICENSE.txt)。

安装包可在该次 Actions 运行页面的 Artifacts 下载，保留 14 天；自动发布成功后也可从 Releases 下载。安装脚本沿用现有安装包的 AppId、可选桌面快捷方式和所有用户开机启动快捷方式，使用管理员安装到 Program Files。工作流打包时排除 VC++ 运行库安装器。

发布任务独立运行，仅该任务申请 contents: write，通过 GitHub 自动提供的 GITHUB_TOKEN 认证。tag 为 7 位提交号，标题为 build <构建标识>，更新日志取本次提交信息。自动发布使用 GITHUB_RUN_NUMBER 作为应用内更新序号，将同一个值编入应用并写入 Release 正文的机器可读标记。新建 Release 时设为 Latest。重跑同一标签时保留已经公开的安装包和发布说明。已有 tag 指向其他提交时直接失败。

镜像站通过独立定时任务拉取 GitHub Release 安装包，校验大小和 SHA-256 后提供下载。镜像随后为符合条件的新构建发布 update.json，客户端通过 Autobuild 查版本和下载安装包。镜像仍独立于 Actions 发布流程。

当前自动构建验证编译、依赖文件和安装包生成，不自动验证界面或实际安装运行。原 Autobuild 脚本中的明文 PAT 应撤销，迁移时不要将其放入仓库。

## 数据与备份

程序将数据保存在用户主目录下的 `ClassTopLand-Next_Data`，与可执行文件所在目录分开：

```text
ClassTopLand-Next_Data/
├── MainConfig.json       # 当前档案、课程条布局、桌面倒计时、外观设置及窗口拦截规则
├── profiles/
│   ├── Default.json      # 首次运行创建的默认档案
│   └── <档案文件名>.json  # 科目、时间线、课表及手动选择的周课表
├── cloud/
│   ├── state.json        # 集控服务器地址、设备凭证与同步状态（含设备秘密，勿分享）
│   └── pending/          # 崩溃恢复用的待应用内容，成功应用后删除
├── plugins/              # 本地 JS 插件包；新插件默认停用
└── plugin-data/          # 插件私有存储；卸载默认保留
```

Windows 下通常为 `%USERPROFILE%\ClassTopLand-Next_Data`。备份整个目录可以保留设置与所有档案；手动修改或恢复文件前，请先退出程序，避免退出时保存的数据覆盖手动更改。集控的 `cloud/state.json` 包含设备凭证，备份可用于恢复同一设备，但不要与非受信方分享。

| 交换格式 | 适用场景 | 注意事项 |
| --- | --- | --- |
| 原生 JSON（`.json`） | 完整档案备份、档案迁移 | 保存档案名称、科目、时间线、周课表及当前周课表选择；应用外观与课程条配置另存于 `MainConfig.json` |
| ClassTopLand tables.json（`.json`） | 与旧版 ClassTopLand 交换常规周课表 | 导入自动识别；导出选择一个周课表，仅保存课程名称与分钟级时间，不保留单双周规则及档案元数据；暂不支持导入非空附加课表 |
| CSES v1（`.yaml` / `.yml`） | 与其他支持 CSES 的课表工具交换 | 交换科目与日课表，不保留档案名称、周课表分组名称和 ID、时间线及当前周课表选择；导入时忽略教室字段 |

导入会创建新档案，不会自动切换或覆盖已有档案。复制和导出使用档案的**已保存内容**，操作前请先保存编辑窗口中的更改。

### ClassTopLand tables.json

JSON 导入按内容区分原生档案与旧版课表，文件不必命名为 `tables.json`。导出时选择“ClassTopLand 课表”格式（与原生 JSON 使用相同扩展名），再选择周课表并确认转换说明。默认选中档案已保存的手动课表，否则选中第一个周课表。

```json
{
  "Mon": [{ "name": "语文", "start": "08:00", "end": "08:45" }],
  "Tue": [],
  "Wed": [],
  "Thu": [],
  "Fri": [],
  "Sat": [],
  "Sun": [],
  "appendixTables": {}
}
```

导入至少需要一个 `Mon`～`Sun` 星期键；缺失星期补为空课表，所有课程按开始时间排序。课程名称不能为空，时间必须为 `HH:mm`，开始早于结束，不能跨日或重叠。导入后建立“常规课表”（全部周次），按课程名称生成科目，简称默认取首字，教师为空，不生成时间线。`appendixTables` 可以缺省或为空对象；空附加课表会被忽略并提示，包含课程的附加课表会导致整个导入失败。

导出仅包含所选周课表，固定输出七个星期键和空的 `appendixTables`。不保留其他周课表、单双周规则、档案名称、周课表及日课表名称、ID、科目简称与教师、未使用科目、时间线或当前课表选择。非零秒会直接截去，确认窗口会列出受影响课程；截去秒后起止时间落在同一分钟的课程无法导出。需要完整备份时请使用原生 JSON。

## 常见问题

- **找不到 Qt / WidgetsPrivate**：确认 Qt 套件安装完整，私有开发文件与 Qt 版本一致，并检查 `CMakeLists.txt` 中的路径及编译器架构。
- **找不到 ElaWidgetTools 或 yaml-cpp 源码**：执行 `git submodule update --init --recursive`，确认子模块已完整下载。
- **子模块下载失败**：检查 GitHub 网络访问和 Git 是否可用，然后重新执行 `git submodule update --init --recursive`。
- **启动时提示缺少 DLL 或 Qt 平台插件**：使用同一 Qt 套件的 `windeployqt` 重新部署，并检查 ElaWidgetTools 动态库是否与程序一同保留。
- **显示「今天没有课程」或「课表不可用」**：检查当天是否有课程、科目和起止时间是否有效，以及是否存在重复匹配；单双周课表需先在快捷面板中手动选择。
- **托盘中找不到图标**：检查 Windows 隐藏图标区域。关闭课程条显示后，仍可从托盘打开设置并重新启用。
