## Agent 上下文压缩导致重复读取（2026-11-07）

定位到未填写模型上下文时采用 32768 默认窗口，但将序列化 UTF-8 字节数直接与 token 预算比较。完整 SDK 约 19 KiB，加上工具定义和系统提示后即触发压缩；旧实现将完整工具结果替换为事件摘要，SDK 只保留前部片段，导致模型反复获取文档与读取文件。

- 改为本地 token 估算，保留窗口的 35% 用于输出；压缩时保留当前用户请求、最新完整 SDK 和最近整组助手／工具消息，包括原始 `reasoning_content`。较早消息才进入摘要；当前回合不会被描述成新恢复的任务。
- 本轮插件编辑授权由宿主明确提供，跨轮授权仍清空。若必需上下文超出预算，明确暂停并保留任务状态，不再丢弃最新结果后自动继续。
- Windows x64、Qt 6.9.3 MSVC 2022 x64、Ninja Release 正式目标编译、链接、完整性规范化及 Qt 部署通过。临时验收入口链接正式应用对象，使用隔离数据和本地模拟 Chat Completions 服务，共通过 446 项断言。
- 默认上下文配置下，模拟模型仅获取一次真实 SDK，连续执行 53 次模型请求，触发 3 次压缩后成功写入并自动启用普通插件；逐次检查 SDK 完整性、原始用户请求、最新结果、思考字段与多工具配对。验证新一轮仍需编辑授权、小窗口和过大文件结果明确停止，以及超大历史可被清理后继续执行。
- 另行链接修改前的 AgentService 进行对照，稳定复现「获取 SDK 后下一次请求缺少完整 SDK」断言失败。未调用真实模型供应商，未写入真实用户数据，未重新验证管理员／UIAccess 或界面缩放。
